# 묘목 관리 영상

홈페이지 첫 화면의 큰 `묘목 재배 영상 보기` 버튼 또는 상단의 `재배 영상` / `묘목 재배 영상` 버튼으로 자료실을 엽니다. 영상은 선택할 때만 YouTube 공식 플레이어를 불러옵니다. 재생 화면의 `영상 닫기`는 목록으로 돌아가며 검색어·필터·스크롤 위치를 유지합니다. 목록 화면의 `닫기`는 자료실을 닫습니다. Escape·배경 클릭으로 닫을 때도 같은 단계 규칙을 사용합니다. 목록으로 돌아갈 때 플레이어가 제거되어 재생을 멈춥니다. 검색·묘목·주제 필터가 견적 입력 상태를 변경하지 않습니다.

## 일반 영상과 짧은 영상(쇼츠)

첫 방문은 `일반 영상`에서 시작합니다. 두 개의 큰 선택 버튼으로 일반 영상 66편과 짧은 영상(쇼츠) 267편을 전환합니다. 두 목록은 처음 20개씩 표시하며 `더 보기`를 누를 때마다 20개를 추가합니다. 각 목록은 검색어·묘목·주제·더 보기 개수·스크롤 위치를 따로 기억합니다. 새 검색이나 필터 변경은 현재 목록을 첫 20개로 되돌립니다.

쇼츠는 모바일에서 세로 썸네일을 2열로 표시하고, 재생 화면도 9:16 비율로 보여줍니다. 영상 닫기는 선택했던 쇼츠 목록으로 돌아갑니다. 썸네일 로드에 실패하면 일반 YouTube 썸네일을 사용합니다. 제목·분류는 계속 볼 수 있습니다. 자동 연속 재생이나 이전·다음 영상 이동은 이 버전에 포함하지 않습니다.

`lib/short-video-catalog.json`은 2026-10-20 채널 Shorts 탭 6페이지를 끝까지 확인한 267편입니다. 일반 영상과 중복된 ID가 없습니다. 공개 제목을 기준으로 분류했으며, 모호한 9편의 설명은 별도로 확인했지만 모두 비어 있었습니다. 특정 묘목을 확정할 수 없으면 공통·기타를 사용하며, 본문 제목의 묘목명이 광고용 해시태그보다 우선합니다. 수집 페이지와 영상별 분류 근거는 `docs/short-video-classification-20261020.json`에 기록합니다.

일반 영상과 쇼츠는 길이가 아닌 YouTube의 실제 탭 구분을 사용합니다. 1분 미만인 일반 영상도 일반 목록에 남습니다. 기존 Apps Script가 주소를 `/watch?v=`로 바꾸더라도 `shorts-<영상ID>` 형태의 콘텐츠ID가 유지되므로 홈페이지 API와 화면이 쇼츠를 인식합니다. 기존 운영 스크립트·배포 URL·환경 변수 변경 없이 동작합니다.

## 영상에서 바로 견적 요청

일반 영상·쇼츠 재생 화면의 `YouTube에서 보기` 옆에 `이 묘목 견적 요청`을 표시합니다. 영상의 검토된 묘목 태그를 사용하고 공통·기타·전체만 있는 영상에는 버튼을 표시하지 않습니다. 카탈로그의 이름과 정확히 일치하거나 끝의 `나무`만 제외하여 일치할 때 같은 이름으로 정규화합니다. 모과나무 → 모과 등이 해당합니다. 유사 수종이나 특정 품종으로 추측해서 바꾸지 않습니다. 첨부된 왕모과 영상 `BCSPY_TAhmM`은 모과로 연결하고 원래 영상 제목을 참고 정보로 유지합니다.

한 수종은 팝업을 열 때 견적에 담고 새 품목 수량은 1주로 시작합니다. 여러 수종이면 큰 선택 버튼에서 필요한 묘목을 고릅니다. 기존 견적 품목·연락처·수량·규격은 유지하며 동일한 묘목을 다시 눌러도 삭제하거나 수량을 늘리지 않습니다. 새로 추가할 때만 빈 행을 재사용하거나 최대 20종 안에서 행을 추가합니다. 품종·규격은 사용자가 확인·수정할 수 있습니다. 카탈로그에 없는 수종도 검토된 영상 태그의 이름을 직접 입력한 견적 품목으로 상담할 수 있습니다.

기존 홈페이지 양식 **한 개**를 팝업과 본문 중 한 위치에서만 렌더링합니다. 닫기 애니메이션 중에도 양식이 중복 표시되지 않습니다. 입력 검증·공식 견적서 선택·내용 확인·접수·접수번호 표시·중복 방지·미확정 접수 재확인은 기존 처리를 그대로 사용합니다. `내용 확인하기` 뒤에 기존 확인창에서 `견적 상담 요청 보내기`를 눌러야 전송합니다. 기존 접수 결과가 미확정이거나 전송 중이면 영상에서 새 품목 추가를 막습니다. 실제 운영 접수 테스트는 보내지 않습니다.

선택한 영상의 제목·원문 주소는 요청사항에 참고 정보로 추가합니다. 같은 주소는 중복하지 않고 입력 제한(일반 1000자, 테스트 900자)을 넘으면 사용자 요청사항을 잘라내거나 덮어쓰지 않습니다. 영상 전용 필드나 새로운 서버 계약을 추가하지 않습니다.

`견적 닫기`·Escape·배경 클릭은 견적 팝업만 닫고 같은 영상 화면으로 돌아갑니다. 영상의 `영상 닫기`는 기존 검색·분류·스크롤을 유지한 목록으로, 목록의 `닫기`는 홈페이지로 돌아갑니다. 견적 팝업을 열 때 플레이어를 제거해 재생 소리를 멈추며, 돌아온 영상은 다시 눌러 처음부터 재생합니다. 영상 재생 시각은 저장하지 않습니다. 견적을 닫아도 작성 중인 내용은 홈페이지 양식에 남습니다.

검증: `tests/video-quote.test.mjs`는 모과·쇼츠 식별, 복수 수종, 유사 수종 분리, 중복 선택, 기존 수량·규격 보존, 20종 제한, 미확정 접수 차단, 참고 정보 길이 및 기존 요청 계약을 확인합니다. 실제 모바일에서 팝업 간 포커스 이동·닫기와 YouTube 재생은 브라우저 QA 환경에서 확인해야 합니다.

## Apps Script 반영

1. 견적 접수용 기존 Apps Script 프로젝트에 `ContentLibrary.gs`를 추가합니다. 이 파일의 소스는 `server-support/ContentLibrary.gs`입니다. 저장소 루트 소스에서는 `server/quote-requests/ContentLibrary.gs`에 대응합니다.
2. `Code.gs`의 기존 `doGet`만 아래처럼 확장합니다. 기존 POST·인증·견적 동작은 유지합니다.

```js
function doGet(e) {
  if (e && e.parameter && e.parameter.action === 'content_library') {
    return json_(publicContentLibrary_());
  }
  return json_(secureServiceInfo_());
}
```

3. 기존 웹앱 배포를 새 버전으로 갱신합니다. 배포 URL·실행 주체·액세스 설정·Script Properties를 유지합니다. `LEGACY_SPREADSHEET_ID`가 있으면 그 운영 파일을, 없으면 `SPREADSHEET_ID`를 사용합니다. 새 권한이나 스크립트 속성이 필요하지 않습니다.
4. `/exec?action=content_library`가 `{ ok:true, catalogVersion:1, items:[...] }`를 반환하는지 확인합니다. 기본 `/exec` 서비스 응답도 계속 확인합니다. GET은 읽기만 하며, 헤더 오류·시트 누락·1000개 초과에서는 비공개 오류 코드만 반환합니다.

사이트 `/api/content-library`는 기존 `QUOTE_SCRIPT_URL`만 사용합니다. Apps Script 응답에서 공개 필드만 다시 검증하고 YouTube 주소를 정규화합니다. 영상 데이터를 받지 못하면 목록 새로고침 실패를 알리고 이미 표시하던 목록을 유지합니다. 빈 정상 응답은 그대로 빈 목록으로 표시하며 최초 영상으로 되돌리지 않습니다. 최초 로컬 등록 영상은 서버 배포 전에도 사용할 수 있도록 포함되어 있습니다.

시트 변경은 다음 창 열기 또는 `새로고침`에서 반영됩니다. 홈페이지를 다시 배포할 필요는 없습니다. 영상 API에서는 blog 행을 노출하지 않습니다. 별도 `묘목 정보·블로그 보기` 화면은 `lib/blog-catalog.json`의 제목·요약·원문 링크를 사용합니다. 자세한 관리는 `docs/blog-library.md`를 참고합니다. 기존 운영시트의 blog 종류는 향후 시트 연동을 위해 예약한 상태입니다.

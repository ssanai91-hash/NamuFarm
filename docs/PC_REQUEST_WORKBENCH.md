# 견적요청 작업대 통합

견적요청 작업대에서 단가 입력, 택배비 선택, PDF 생성·미리보기, 문자·메일 발송을 처리합니다.
고객 전달 줄의 **견적완료**를 누르고 확인해야 서버 상태와 로컬 확정 견적 엑셀이 갱신됩니다.
PDF 생성이나 문자·메일 발송만으로 견적 상태가 바뀌지는 않습니다.

- 선불 택배비는 합계에 포함하며 후불은 별도로 표시합니다.
- 단가·택배비 변경 시 생성했던 PDF를 무효화합니다. 새 PDF를 생성한 뒤 첨부해야 합니다.
- PDF 파일명은 생성 버튼 아래 표시합니다. 메일 발송 시 해당 PDF 첨부 여부를 확인합니다.
- 발송에 사용한 입력은 다시 열 수 있도록 보존하지만, 확정 엑셀에는 자동 등록하지 않습니다.
- 합계와 고객 전달 사이를 선과 여백으로 구분합니다. 문자·메일 버튼 왼쪽 안에 전송 상태를 표시합니다.
- 문자 보내기, 메일 보내기, 견적완료를 같은 줄에 배치하며 하단에는 닫기만 표시합니다.
- 현재 견적을 문자 또는 메일 중 한 경로로 전송해야 견적완료할 수 있습니다. 미전송 상태에서는 알림을 표시합니다.
- 문자는 접수/대기가 아닌 최종 성공, 메일은 서버 전송 완료 응답을 기준으로 합니다.
- 전송 시 견적 내용의 지문을 로컬 발송 기록에 저장합니다. 단가·택배비 등 내용이 바뀌면 재전송이 필요합니다.
  지문이 없는 구버전 발송 기록은 현재 견적과의 일치를 확인할 수 없어 재전송이 필요합니다.
- 확정견적 목록과 팝업은 로컬 엑셀에 저장된 결과를 확인하는 용도로만 사용합니다.
  결과 창에는 고객 정보, 품목·금액, 저장된 택배비, 문자·메일의 전송 결과·시각·수신처와 요청사항을 표시합니다.
  공식견적서 생성·미리보기, 택배비 설정, 문자·메일 발송, 발송완료·입금확인 처리는 이 창에서 제공하지 않습니다.
  하단에는 닫기만 표시하며, 목록의 삭제 버튼도 제거합니다.
- 결과를 열고 닫아도 저장·동기화·발송·상태변경을 실행하지 않습니다.
  저장된 택배비 0원이나 수신처를 편집 기본값·현재 서버 요청 정보로 덮어쓰지 않습니다.
- 견적요청 작업대의 작성·문서 생성·전송·견적완료 기능과 판매관리 화면은 유지합니다.

## 서버 배포

요청 상태(`신규`)에서도 문자·메일을 보내려면
`server/quote-requests/SecureCommerce.gs`를 운영 Apps Script에 반영하고
기존 웹앱 배포의 새 버전으로 업데이트해야 합니다.
기존 배포 URL과 시트 설정을 유지합니다.
이 커밋 자체는 운영 서버를 배포하거나 고객에게 메시지를 보내지 않습니다.

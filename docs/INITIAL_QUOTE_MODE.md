# 초기 앱에 견적 모드 추가

개발 브랜치: restore/android-initial-20260927.

- 상단 탭/좌우 이동: 견적 → 매매 → 농원·묘목.
- 첫 화면은 견적 모드. 매매·관리 화면 및 기존 리소스는 초기 커밋의 원문 그대로 유지한다.
- 견적 화면은 기존 견적 앱의 목록·입력 화면·발송 확인 워크플로를 재사용한다.
- 운영 서버는 이미 배포된 snapshot_requests / save_quote_pricing / close_request API를 사용한다.
- 농원·묘목 동기화와 동일한 기기 연결 사용. 서버 주소 입력 화면은 추가하지 않는다.

## 견적 처리

1. 가져오기로 신규·확정 견적을 기기에 보관한다.
2. 고객 요청을 선택해 단가와 배송비를 입력한다.
3. 문자·메일 버튼이 휴대폰의 작성 앱에 수신처와 견적 본문을 채운다.
4. 판매자가 실제 발송 후 견적완료에서 발송 방법을 확인한다.
5. 확정 대기 기록을 먼저 저장하고 서버 확인 후에만 확정 목록으로 이동한다.

외부 작성 앱을 연 것만으로 발송 완료로 표시하지 않는다.
확정 응답 유실 시 같은 입력으로 다시 확인할 수 있으며, 자동으로 문자·메일을 다시 보내지 않는다.
확정 목록은 이 기기의 기록과 운영 시트에서 확정된 견적을 중복 없이 표시한다.
다른 기기의 확정 단가·배송비도 서버의 quotePricing을 읽어 조회한다.

## 저장과 보존

기존 NamuFarm.db(농원·묘목·재고·주문)는 변경하지 않는다.
견적 요청 캐시는 NamuFarmQuotes.db에 분리하고, 발송·확정 저널은 quote_workflow_v1에 저장한다.
목록 전체의 페이지·전체 건수·스냅샷 식별자를 검증한 뒤 한 트랜잭션으로 반영한다.
중간 다운로드 실패나 불완전한 응답이면 기존 기기 목록을 유지한다.
읽지 못하는 이전 암호화 요청은 별도로 보관하며 원본 기기 확인 안내를 표시한다.

## 빌드와 확인

applicationId: com.example.namufarm.original, versionCode: 3.
기존 초기버전 APK와 같은 서명으로 업데이트한다.
GitHub Actions에서 기존 UI/리소스 동일성, 마스터 동기화, 견적 워크플로,
부분 다운로드 보존, 확정 단가 조회, 문자·메일 Intent를 검사하고 release APK를 만든다.
운영 시트에 시험 견적을 추가하거나 고객에게 시험 문자를 전송하지 않는다.
실기기에서 문자·메일 앱의 발송과 최종 시트 이동 확인은 설치 후 수행한다.

# 나무팜 구글시트 2파일 전환 (2026-10)

운영 목표: `나무팜_견적_YYYY`(홈페이지·안드로이드·나피)와
`나무팜_주문_YYYY`(나피 PC 전용)만 **활성 장부**로 사용한다.
각 연도 파일의 업무 원본은 `01월`~`12월` 탭에 저장한다.
단가 입력·견적확정은 견적용 파일, 입금확인·배송완료와 매출은 주문용 파일에 기록한다.

> **중요:** GitHub 커밋과 Apps Script 소스 갱신만으로 실서버 데이터는 전환되지 않는다.
> 기존 Apps Script 프로젝트 및 웹앱 /exec URL, 디바이스 인증 설정을 유지해야 한다.
> 절대로 옛 운영 시트를 먼저 삭제하지 않는다.

## 실제 전환 (Work 또는 스크립트 소유자가 수행)

1. 현재 `나무팜_견적관리_운영` 파일을 보존하고 사본으로 백업한다. 실제 스크립트에서 원본과 시트 ID를 확인한다.
2. 기존 **동일 Apps Script 프로젝트**에 `AnnualLedgers.gs`, `MonthlyStorage.gs`, `SecureCommerce.gs`,
   `Code.gs`, `TwoBookCutover.gs` 최신 버전을 함께 갱신한다. `appsscript.json`의 Drive API v3 고급 서비스를 유지한다.
3. 홈페이지 접수·PC/앱 업데이트가 없는 짧은 점검 시간에 **스크립트 편집기 소유자 실행**으로 순서대로
   `setupAnnualQuoteOrderLedgers()` → `cutoverToTwoBooks()`를 실행한다.
   반환된 `quoteFileId` 및 `orderFileId`와 생성한 연도별 파일 이름, 12개월 탭을 기록한다.
4. 서버가 보존한 `LEGACY_SPREADSHEET_ID`를 확인하고 기존 운영 파일은 **읽기 전용 백업**으로 보관한다.
   장부·접수번호·고객자료·매출 이력을 임의로 삭제하거나 초기화하지 않는다.
5. 서버 응답·견적용 파일·주문용 파일의 **기존 데이터 개수와 원본 값**을 운영자가 확인한 뒤,
   **기존 웹앱 배포 URL을 변경하지 않고** 업데이트 버전으로 배포한다.
6. 운영자가 PC와 안드로이드에서 실제 데이터를 조회하고 새 견적 반영, 금액 동기화, 입금·배송 상태를 확인한다.
   APK 빌드 완료와 Apps Script 배포 완료를 혼동하지 않는다.

## 현재 배포 전 주의

- 두 파일로 최종 활성화하기 전까지 기존 운영 파일이 서버의 실질 원본이다.
- 새 `save_quote_pricing` API는 Android 가격 확정과 PC 가격 가져오기에 필요하다.
  배포되기 전 신형 앱으로 견적확정을 하면 서버 측에서 지원되지 않는다.
- 1차 Android는 신규 요청·견적 작업대만 제공하며, 주문/판매 기록 접속을 비활성화했다.
  PC 나피는 견적과 주문 관리, 견적 PDF·문자·메일 발송을 맡는다.
- 기존 Apps Script가 운영 구글시트에 *바인딩*된 프로젝트라면, 백업 파일 자체를 삭제하기 전에
  스크립트 프로젝트의 독립성 및 배포 URL 유지 여부부터 확인한다.

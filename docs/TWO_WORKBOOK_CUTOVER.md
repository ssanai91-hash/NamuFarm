# 나무팜 2파일 · 견적 2탭 전환

## 확정한 구조

| 파일 | 탭 | 사용 |
| --- | --- | --- |
| `나무팜_견적_YYYY` | **견적요청**, **견적확정** (정확히 2개) | 홈페이지 접수 / 나무팜 Android · 나피 PC의 견적확정 |
| `나무팜_주문_YYYY` | **01월 ~ 12월** + 서버용 보조 탭 | 나피 PC 전용 입금확인 → 배송완료 |

견적을 확정할 때 확정 탭에 같은 요청번호로 먼저 저장·검증하고, 요청 탭의 해당 행을 정리한다.
원본 요청 정보와 판매자의 품목별 판매 단가는 확정 행의 JSON에 보존한다.
서버는 요청번호의 중복 및 중단된 이동을 감지·복구한다.
나피·Android의 기존 연결 URL과 인증정보는 유지한다.

**주의: GitHub 커밋이 곧 Google Apps Script 배포나 시트 전환을 의미하지 않는다.**

## 배포 및 전환 절차 (기존 운영 Apps Script 소유자만)

1. `나무팜_견적관리_운영`과 연결 설정의 **기존 자료를 백업**하고, 웹앱 URL과 Apps Script 프로젝트 ID를 기록한다.
2. 동일한 기존 Apps Script 프로젝트에 `Code.gs`, `SecureCommerce.gs`, `MonthlyStorage.gs`,
   `AnnualLedgers.gs`, `TwoTabQuotes.gs`, `TwoBookCutover.gs` 최신 코드를 반영한다.
   `appsscript.json`의 Google Drive API v3 고급 서비스를 유지한다.
3. **전환 전에** 기존 Apps Script 웹앱의 동일한 배포 ID·`/exec` URL로 새 코드를 게시한다.
   이때 기존 저장 모드와 데이터는 그대로 유지되므로 배포와 장부 전환을 혼동하지 않는다.
4. 홈페이지 접수·PC/Android 견적 확정·입금처리가 **없는 점검 시간**에 소유자 권한으로
   `setupAnnualQuoteOrderLedgers()`를 실행한다. 이어서 같은 점검 시간에
   `cutoverToTwoBooks()`를 실행한다. 기존 견적을 상태별 2탭으로,
   기존 주문을 입금연도·월에 맞는 탭으로 복사하고 **원본과 일치하는지 확인한 후에만**
   운영 저장 위치를 전환한다.
5. 반환한 `quoteFileId`, `orderFileId`를 기록한다. 견적 파일에 `견적요청`·`견적확정`
   이외의 탭이 없는지 확인한다. 판매 파일의 12개월 탭도 확인한다.
6. 새 Android APK와 나피 PC 버전은 배포·전환이 완료된 뒤 실제 동기화에 사용한다.
   서버 배포가 먼저 완료돼야 신규 `save_quote_pricing` API가 작동한다.
7. 브로가 홈페이지·PC·Android에서 목록 조회 및 견적확정 → 작업대 반영, 나피 입금확인 →
   주문 시트 반영, 배송완료를 직접 확인한다.

## 데이터 보존 및 작업 중단 기준

- 기존 운영 파일은 **실서버에서 제외하지만 즉시 삭제하지 않는다.** 완료 후 읽기 전용 백업으로 보관한다.
- 스크립트 설정의 `LEGACY_SPREADSHEET_ID`가 백업을 가리키도록 남긴다. 이 값은
  정상 업무 API가 아닌 소유자 복구 시에만 사용한다.
- 원본과 복사본이 일치하지 않거나 기존 견적이 들어 있는 예상 외 탭이 발견되면
  전환을 **중단**한다. 강제로 초기화하거나 수동으로 행을 지우지 않는다.
- 판매/주문 원장의 입금·배송·고객·재고·매출 내역은 보존한다.
- Android 1차 버전은 견적만 다루며 주문용 파일에 접근하지 않는다.
- 컴파일은 Windows에서 `gradlew.bat :app:assembleDebug` 및 `desktop/build_windows.bat`을 사용한다.
  APK·EXE 생성과 실제 Google Apps Script 배포는 서로 다른 작업이다.

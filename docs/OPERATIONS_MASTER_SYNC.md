# 초기 앱의 운영 시트 연결

개발 기준: `restore/android-initial-20260927`, 초기 화면·색상·버튼 배치 유지.

## 연결 범위

- 기존 운영 Apps Script의 인증된 POST API 사용. 현재 배포된 서버의 수정·재배포 불필요.
- 운영 통합문서 `나무팜_견적관리_운영`의 `농원관리`, `묘목관리` 연결.
- 기존 재고·견적·주문은 기기에 유지. 초기 재고·주문 API는 운영 서버 규격과 달라 이번 연결에서 전송하거나 가져오지 않는다.
- 동일 이름의 웹사이트 상품 목록과 견적 모드 추가는 별도 작업이다.

## 저장과 동기화

1. 농원·묘목 저장 시 Room 데이터와 전송 대기 항목을 한 트랜잭션으로 저장.
2. 바로 서버 전송 시도. 실패하면 기기 데이터와 대기 기록 유지.
3. 동기화 버튼은 농원·묘목 대기를 순서대로 전송하고 최신 목록을 가져온다.
4. 기존 목록이 있으면 화면을 열 때마다 서버를 호출하지 않는다. 첫 다운로드 완료 여부는 별도 저장한다.
5. 로컬 ID와 서버 ID를 `master_links`로 연결. 재고가 참조하는 로컬 ID는 변경하지 않는다.
6. 수정 요청에 서버 버전과 영속 작업 UUID 사용. 충돌하면 로컬 수정을 덮거나 대기 항목을 버리지 않는다.
7. 농원에 로컬 재고가 있으면 삭제를 거절한다. 서버도 양수 재고가 있는 농원 삭제를 거절한다.

기기 DB 버전 12 → 13은 연결 테이블만 추가한다. 파괴적 DB 초기화는 사용하지 않는다.
예전 버전 10·11의 배송비 컬럼 누락도 보존 마이그레이션으로 보완한다.

## 검증

GitHub Actions에서 초기 UI·리소스가 원본 커밋과 같은지 검사하고 JVM 단위 테스트 및 release APK를 빌드한다.
운영 데이터에 시험 농원·묘목·주문을 생성하지 않는다.
실기기에서 추가·수정 → 시트 확인, 오프라인 추가 → 동기화 재전송 확인은 설치 후 수행한다.

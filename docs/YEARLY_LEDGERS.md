# 견적 / 입금확인 주문 장부 분리

## 운영 방식

- 견적: `나무팜_견적_2026`의 `01월`~`12월` 시트. 접수시각의 한국 시간 기준 월에 저장합니다.
- 주문: `나무팜_주문_2026`의 `01월`~`12월` 시트. 로컬의 최초 `paidAt`(입금확인시각)을 한국 시간으로 환산한 월에 저장합니다.
- 새 연도의 파일은 해당 연도 첫 저장 때 자동 생성합니다. 초기 설정 시에는 현재 연도의 두 파일을 준비합니다.
- 입금 확인은 기존 PC `save_sale` 전송 대기 → 서버 저장 → 응답 확인 흐름을 그대로 사용합니다.
- 입금 이후 견적 원본은 `견적발송완료`에 남깁니다. 배송·취소는 주문 원본에만 반영합니다.
- 배송월이 바뀌어도 주문을 옮기지 않습니다. 주문번호/견적요청 ID, 버전 검사와 기존 재시도 기록으로 중복과 오래된 덮어쓰기를 막습니다.
- PC 화면은 연결된 주문 상태를 로컬에서 표시합니다. 구글 견적 행에는 입금/배송 상태를 다시 쓰지 않습니다.
- 과거 연도와 기존 단일 시트 주문도 함께 조회합니다. **기존 자료를 자동 이동하거나 삭제하지 않습니다.** 이 기능은 새 입력의 저장 위치를 바꾸는 전환입니다.
- 관리용 기존 스프레드시트의 `연도별장부`와 `주문저장위치`는 파일 위치·식별자만 저장하는 내부 표입니다. 운영자가 따로 관리할 장부가 아닙니다.
- 기존 개인정보 보관 정책(견적 30일, 종료 주문 5년)은 변경하지 않았습니다. 연도별 파일 구성이 보관기간을 연장하지는 않습니다.

## 운영 반영

1. 기존 Apps Script 프로젝트에 `Code.gs`, `SecureCommerce.gs`, `MonthlyStorage.gs`, `RecoverySetup.gs` 및 새 `YearlyLedgers.gs`를 같은 버전으로 넣습니다. 기존 `appsscript.json`의 Drive v3 서비스와 권한을 유지합니다.
2. Apps Script 편집기에서 소유자 계정으로 **`setupYearlyLedgers()`를 한 번 실행**합니다. 권한 승인이 필요하면 승인합니다. 반환값의 `ready: true`, 두 파일 ID와 해당 파일의 월 탭을 확인합니다. 이 함수는 다시 실행해도 기존 주문을 복제하지 않습니다.
3. 기존 웹 앱 배포의 버전을 갱신합니다. 배포 URL/연결파일/PC 로컬 보관함을 바꾸거나 초기화하지 않습니다.
4. PC 0.4.9 코드를 적용하고 기존 동기화 버튼을 사용합니다. 실제 입금 확인 1건, 배송 처리 1건으로 운영 환경의 권한과 연결을 점검합니다.

소스 커밋만으로 기존 Apps Script 웹 앱 배포가 바뀌지는 않습니다. 이 변경의 자동 테스트는 가짜 고객과 메모리 시트를 사용하는 테스트이며 실제 고객 장부에 쓰지 않습니다.

## 검증

```sh
node --test server/quote-requests/tests/yearly-ledgers.test.cjs
PYTHONPATH=desktop:desktop/tests python -m unittest test_yearly_ledgers test_local_sync -v
```

서버 신규 테스트 20개와 실제 PC Manager → 실제 Apps Script 소스를 연결한 신규 통합 테스트 3개를 추가했습니다. 월말/연말 한국 시간 경계, 원본 월 유지, 견적 원본 유지, 정렬 후 갱신, 재클릭·응답 유실·중간 실패, 버전 충돌, 과거 장부 조회, 이전 단일 시트 전환 이력과 개인정보 만료를 검사합니다.

수정 전 서버 전체 136개 중 8개가 기존 구매확정/판매완료·견적 삭제 정책 관련 기대값으로 실패했습니다. 수정 후 전체 156개 중 148개 통과, 같은 8개 실패이며 새 실패는 없습니다. 기존 실패를 숨기거나 통과 처리하지 않았습니다. 별도로 기존 PC `test_simple_connection`에서도 서버 URL/연결 방식 관련 실패가 확인되어 전체 회귀 테스트 통과로 보고하지 않습니다.

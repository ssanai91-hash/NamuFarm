# 온라인 요청 → 수동 견적 → 입금 주문

- 홈페이지가 반환한 UUID 접수번호를 그대로 PC 요청함, Android 요청함과 견적 연락처에 보관합니다. 다른 접수번호를 새로 만들어 연결하지 않습니다.
- Android 첫 화면의 판매 재고를 온라인 요청 목록으로 교체했습니다. 연결 설정은 상단에 유지합니다. 과거 재고 데이터와 전송 대기는 삭제하지 않습니다.
- 온라인 견적 요청함 버튼은 재고 전송과 독립적으로 요청을 가져옵니다. 검증한 요청과 읽은 순번은 같은 Room transaction에서 저장합니다. 실패하면 기존 목록과 순번을 유지합니다.
- 요청을 선택해 수동 견적 작성: 고객·연락처, 각 묘목, 배송비를 별도 박스로 표시합니다. 요청 품목·규격·수량을 미리 채우며 단가는 판매자가 정합니다. 농원·재고·마스터 등록은 필요하지 않습니다.
- 저장한 견적 상세에서 문자 초안, 공식 PDF·문자 이미지·이메일 첨부를 엽니다. 실제 전송은 판매자가 해당 앱에서 실행합니다. 발송 완료 확인 시 최초 발송 시각을 기록하고 오늘 견적에 1회 집계합니다. 초안 저장·파일 열기는 발송으로 계산하지 않습니다.
- 입금 완료 · 주문 등록은 구매확정과 입금확인 두 버전의 암호화 전송 항목을 하나의 로컬 transaction에 저장합니다. 기존 서버의 상태 전이 검증을 그대로 사용합니다. 응답 유실 시 같은 이벤트로 재전송하며 중복 주문은 막습니다.
- 오늘 주문은 한국 시간 기준 실제 입금 확인일로 집계합니다. 견적 원본·발송 시각은 주문 전환과 문의 종료 후에도 유지합니다. 오늘 견적은 감소하지 않습니다. 판매 기록 보관 기한이 끝나면 연결 견적도 함께 정리합니다.
- PC 요청함은 접수번호 검색·표시 및 독립 새 요청 가져오기를 제공합니다. 판매 수정 전송이 대기 중이어도 요청을 가져오며 판매 캐시와 전송 대기는 건드리지 않습니다. 견적 작성·문자/PDF 발송은 Android에서, 입금·배송·비용 관리는 동기화된 Android/PC에서 처리합니다.
- 발송 전 견적 초안과 발송 체크는 작성한 휴대폰에 저장됩니다. PC에는 온라인 접수와 주문 전환 후의 암호화 판매·발행 문서가 동기화됩니다. 여러 기기 사이의 미주문 견적 초안 편집은 제공하지 않습니다.
- Room 15→16 migration은 sent_at을 0으로 추가합니다. 과거 견적의 발송 여부를 임의로 추정하지 않습니다. 기존 Apps Script v4와 호환되므로 이번 수정에 서버 재배포는 필요하지 않습니다.

검증: 요청 조회와 재고 대기 독립성, 페이지 실패의 순번 보존, 무재고 견적의 발송·입금 집계 유지, 중복 구매 차단, 입금 transaction 실패 복구, schema migration, Python/Apps Script 연동 및 실제 Compose/Qt 화면 검사를 수행합니다. 운영 휴대폰 설치 및 실제 문자·메일 수신은 별도 실기기 확인 대상입니다.

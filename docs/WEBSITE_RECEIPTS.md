# 홈페이지 견적 접수 완료 기준

홈페이지는 고객이 작성한 견적 요청을 접수 서버를 통해 구글시트에 전달합니다. 구매·결제·판매 상태를 홈페이지에서 만들지 않습니다. 공식 견적서 요청 여부, 수신인, 이메일 및 문자/이메일 답변 방법은 고객 요청 원문에 포함하여 암호화합니다.

## 번호와 날짜

- 내부 연결키 `requestId`는 기존 UUID를 유지합니다. 고객이 같은 내용을 재전송하면 같은 UUID를 재사용합니다.
- 서버가 시트를 저장하는 잠금 안에서 한국 날짜별 고객용 `NFQ-YYYYMMDD-NNNN` 번호를 한 번 발급합니다. 날짜는 고객 기기 시계가 아닌 서버 접수시각을 기준으로 합니다.
- 일별 번호를 Script Properties에 먼저 예약하고 요청 행과 함께 저장합니다. 실패하면 순번이 건너뛸 수 있지만 번호를 재사용하지 않습니다. 동기화 접수순번과 고객용 번호는 별개입니다.
- 기존 A:P 열은 유지하고 Q `견적접수번호`, R `접수시각(한국)`를 추가합니다. UTC 원본 접수시각은 C에 유지합니다. 시트 시간대는 `Asia/Seoul`입니다.
- 저장 성공 응답에 내부 UUID, 고객용 접수번호, 최초 UTC 접수시각과 한국시간을 포함합니다. 홈페이지는 번호와 날짜가 일치하는 응답을 받은 후에만 완료 화면을 표시합니다.
- 삭제 동기화·보관 종료·정렬·다음 날 재전송에도 번호와 최초 접수시각은 유지합니다.

## 기존 자료와 배포

기존 프로젝트의 `Code.gs`, `SecureCommerce.gs`를 적용하고 `setupQuoteRequests()`를 실행합니다. 기존 요청 행은 접수시각 순으로 새 표시 번호를 부여하며, 기존에 부여된 번호는 보존합니다. 원래 UUID·접수시각·내용해시·암호문·동기화 순번과 판매 자료는 바꾸지 않습니다. 기존 Q/R에 다른 내용이 있으면 중단합니다.

기존 웹앱의 URL, Script Properties의 연결·보안 설정, 실행 주체와 접근 설정을 유지한 채 새 버전으로 배포합니다. API 버전 4를 유지하며 조회 응답의 추가 표시 항목은 기존 앱과 PC가 무시해도 기존 동기화에 영향이 없습니다. 앱·PC의 새 접수번호 표시 연결은 후속 작업입니다.

홈페이지 환경에서 `QUOTE_TEST_MODE=false`, 실제 견적 상담 목적의 개인정보 안내를 설정합니다. 고객 정보 암호화와 중복 방지 동작은 유지합니다. 운영 확인용 요청은 가상 연락처와 명확한 테스트 문구를 사용하며 실제 문자·이메일을 발송하지 않습니다.

검증은 서버·홈페이지 회귀 테스트, 한국 자정 경계, 다음 날 재전송, 저장/응답 실패, 기존 행 보존 및 시트 실제 저장 확인을 포함합니다.

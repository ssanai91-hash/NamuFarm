# 공통 판매번호·배송준비 적용

1. 기존 Apps Script 프로젝트에서 `Code.gs`, `SecureCommerce.gs`를 이 커밋으로 갱신합니다.
2. 같은 프로젝트에 `SoldNumbers.gs`를 추가합니다. 다른 스크립트·설정·장부는 유지합니다.
3. 기존 웹앱 배포를 **새 버전으로 업데이트**합니다. 배포 ID와 `/exec` 주소를 바꾸지 않습니다.
4. 두 PC 모두 새 나피를 사용하고, 서버에서 가져오기를 누릅니다.

공통 번호는 한국 날짜 기준 `SOLD-YYYYMMDD-0001` 형식이며 PC마다 20개씩 서로 다른 구간을 예약합니다.
미사용·취소 예약번호는 재사용하지 않아 중간 번호가 비거나 등록 순서와 번호 순서가 다를 수 있습니다.
번호 구간을 예약한 뒤에는 입금확인 시 로컬 DB에서 배정합니다. 새 날짜·구간 소진 시에는 서버 연결이 필요합니다.
예약 이력은 운영 장부의 `판매번호예약` 시트에 자동 생성됩니다.
기존 `PC_` 판매 건은 서버 가져오기 때 공통 SOLD 표시번호를 발급합니다. `판매번호연결` 시트에 연결을 보관하므로
두 PC에서 같은 번호를 표시하며, 기존 주문의 식별키·견적 연결·변경 이력은 유지합니다.
로컬 내보내기·가져오기에도 이 연결번호를 포함합니다. 발급 전에는 `SOLD 번호 발급 대기`로 표시합니다.

서버 업데이트 전에는 견적·기존 판매자료를 유지하며, 신규 SOLD 번호 발급은 안내 메시지와 함께 중단합니다.
초기화·장부 전환 함수를 실행하거나 기존 자료를 삭제할 필요가 없습니다.

판매관리에서 수령인·연락처·우편번호·주소·로젠 송장번호를 입력하고 **배송준비완료**를 눌러야
배송·송장 목록과 로젠 XLS 내보내기에 포함됩니다. 송장번호는 로젠에서 발급받은 11자리 번호를 사용합니다.
실제 운송장 출력은 기존처럼 로젠 프로그램에서 진행합니다. 배송준비완료는 배송완료와 별개입니다.

이번 버전은 구매취소를 입금확인으로 복원하고, 취소·완료된 주문의 배송메모도 저장할 수 있습니다.
복원 후에는 배송준비완료를 다시 확인합니다. 원가 확인 없이 배송완료 처리할 수 있도록 서버도 함께 갱신해야 합니다.
주소찾기는 판매관리 팝업 안의 작은 브라우저에서 검색한 주소·우편번호를 자동 입력합니다. 상세주소는 직접 입력합니다.
송장번호 오른쪽의 입력 버튼은 숫자·하이픈 키패드를 엽니다. 입력 후 수정 저장 또는 배송준비완료로 보관합니다.
판매관리에서는 배송준비완료까지만 처리하고, 실제 배송완료는 배송·송장 카테고리에서 선택한 한 건에 적용합니다.

# 고객문의 접수 · 기존 Apps Script 재배포

2026-10-24 KST. 홈페이지와 서버 소스 변경이며, Apps Script 운영 재배포는 사용자가 직접 한다.

## 적용 파일과 순서

기존 홈페이지 견적 접수를 처리하는 **같은 Apps Script 프로젝트**를 연다. 기존 속성·배포 ID·견적/주문/운영 장부와 고객자료를 보존한다.

1. 이 폴더의 최신 [`Code.gs`](Code.gs), [`SecureCommerce.gs`](SecureCommerce.gs) 내용을 각각 같은 이름의 파일에 반영한다.
2. 스크립트 파일 **`CustomerInquiries`**를 추가하고 [`CustomerInquiries.gs`](CustomerInquiries.gs)의 전체 내용을 넣는다. 다른 기존 `.gs` 파일은 유지한다.
3. 편집기의 실행 함수에서 **`setupCustomerInquiries`**를 한 번 실행한다. 메시지는 보내지 않는다. 권한 승인이 표시되면 기존 운영 계정으로 승인한다.
4. 실행 로그에 나오는 비공개 Google Sheets 링크를 확인한다. **`나무팜_고객문의_2026`** 파일과 **`고객문의`** 시트가 생성된다. 실제 파일 생성은 이 함수를 실행할 때 이루어진다. 반복 실행해도 등록된 같은 파일을 사용한다.
5. **배포 → 배포 관리 → 기존 웹 앱의 수정(연필) → 버전 ‘새 버전’ → 배포**로 갱신한다. 실행 주체·접근 설정·기존 `/exec` URL은 유지한다. 홈페이지의 서버 주소·비밀키를 바꾸지 않는다.
6. 홈페이지를 새로고침하고 **문의 남기기**를 연다. 잠시 후 접수 가능 상태가 갱신된다. ‘문의 보내기’ 자리에 ‘접수 준비 중’이 표시되면 그 버튼을 눌러 접수 가능 여부를 다시 확인한다.

Apps Script 편집기 진입: <https://script.google.com/home> (기존 견적 접수 프로젝트 선택).

파일 이름의 연도는 한국시간 접수일 기준이다. 다음 연도의 첫 새 문의에서 `나무팜_고객문의_2027` 파일이 자동 생성된다. `INQUIRY_BOOKS` 속성이 연도별 파일 ID를 보관하므로 임의 삭제하지 않는다. 기존 견적/주문 파일을 고객문의용으로 지정하거나 덮어쓰지 않는다.

## 홈페이지 반영 범위

- 선택한 중앙 팝업, 문의 종류 `묘목·재배 / 구매·배송 / 기타`, 이름·휴대폰 번호·선택 이메일·문의 내용·동의 및 전화 상담.
- 문의 내용은 **5줄, 최소 높이 8.5rem**, 최대 2,000자. 작은 화면·키보드 표시 중에는 본문만 스크롤되고 하단 동작은 분리된다.
- 파일 첨부 없음. 질문·연락처는 홈페이지에 공개되지 않는다.
- 모바일 빠른 상담의 왼쪽 버튼은 ‘문의 남기기’이며 전화 상담은 문의 창 하단·메뉴·푸터에 있다. PC 메뉴·푸터·견적 양식 안내에서도 문의를 연다.
- 저장 확인 응답의 문의번호는 **`INQ-YYYYMMDD-0001`**. 견적번호와 분리한다.
- 타임아웃·결과 불명 시 문의 ID와 입력값을 같은 탭에 임시 보관하고 같은 ID로 재확인한다. 견적 폼의 임시 저장과 분리한다.
- 재배포 및 초기 설정 전에는 큰 안내 박스 대신 보내기 버튼 자리에 ‘접수 준비 중’을 표시하고 전화 상담을 제공한다. 테스트 모드에서는 일반 문의 접수를 막는다.

## 나피·Android 연결 계약 (나피 구현, Android는 다음 단계)

공개 홈페이지는 `submit_customer_inquiry`만 호출한다. 아래 조회·답변 액션은 기존 `connectionKey` 또는 `deviceToken` 인증이 필요하다. 인증키를 홈페이지나 고객에게 노출하지 않는다.

| action | 입력 | 결과/주의 |
| --- | --- | --- |
| `list_customer_inquiries` | `afterSequence: 0`, 선택 `limit: 1..100` | `inquiries`, `hasMore`, `nextSequence`. 모든 등록 연도 통합. 계속 조회할 때 반환한 `nextSequence` 사용 |
| `save_inquiry_reply` | `requestId`, 현재 `revision`, UUID v4 `eventId`, `replyText`, `replyChannel: sms 또는 email` | 답변 초안 저장. 문자 초안 900자/메일 2,000자. 답변 완료로 바꾸지 않음 |
| `send_inquiry_reply` | `requestId`, 저장 후 받은 `revision`, UUID v4 `deliveryId` | 저장된 답변만 저장된 고객 연락처로 발송. 같은 `deliveryId` 재호출은 재발송하지 않음 |
| `set_inquiry_status` | `requestId`, 현재 `revision`, UUID v4 `eventId`, `status: open 또는 closed`, `note: 1..500자` | 전화 상담 완료·다시 열기. 원문/기존 발송 이력 유지, 발송 중·문자 결과 대기 중에는 거절 |
| `inquiry_sms_status` | `requestId` | 서버에 저장된 SOLAPI 메시지 ID로 조회. 문자 성공 코드 `4000`을 확인해야 답변 완료 |

클라이언트는 먼저 로컬 DB에 초안과 UUID를 저장하고, 서버 성공 응답에 담긴 revision/변경순번/발송 상태를 반영한다. `CONFLICT`는 다른 앱에서 수정한 상태이므로 다시 불러와 비교하며 강제 덮어쓰지 않는다. 증분 목록은 삭제를 추론하는 전체 스냅샷이 아니다. `expired: true`가 오면 로컬 개인정보도 지우되 최소 동기화 식별자는 유지한다. 통신 중단 시 마지막으로 저장한 커서 다음부터 재개한다.

메일은 MailApp 발송 호출 성공 시 `closed`로 기록하며 수신함 도착·읽음까지 보장하는 의미는 아니다. 문자는 SOLAPI 접수 상태 `pending` 동안 `open`를 유지한다. 발송 중/결과 불명(`sending`/`unknown`)이면 자동 재발송 및 초안 변경을 막는다. 운영자가 공급자 발송 이력으로 확인하고 처리할 사항이며, 일반적인 재시도 버튼으로 새 `deliveryId`를 만들면 안 된다. 문자 전송 실패가 확정된 뒤에만 수정·재발송할 수 있다.

**나피는 고객문의 메뉴·로컬 DB·연도별 엑셀·답변창까지 구현했다. Android 문의 화면은 아직 미구현이다.**

나피 사용 순서: 고객문의 → 불러오기 → 문의 선택 → 답변하기 → 문자 보내기 또는 메일 보내기. 고객이 이메일을 남기지 않으면 메일 버튼은 비활성이다. 실행파일의 `자료` 폴더에 `나무팜-고객문의-YYYY.xlsx`가 자동 저장된다. 엑셀은 조회용 사본이며 수동 편집을 자동으로 가져오지 않는다. 입력 중 답변은 로컬 DB에 자동 보관되고, ‘초안 저장’은 서버에도 저장한다. 실제 발송은 발송 확인창에서 동의한 경우에만 진행한다. 전송 실패/응답 유실 시 ‘결과 확인’은 같은 작업 ID를 재사용하며 새 답변을 자동 발송하지 않는다.

`customerInquiryWorkflow: 2`가 새 상태 API 식별 기준이다. 신규 행은 `open`, 메일 발송 호출 성공/문자 최종 성공/전화 상담 완료는 `closed`로 기록한다. 기존 한글 상태는 호환 조회하고 새로 변경되는 행부터 영어 상태를 사용한다. `expired: true`는 개인정보 만료로서 상태와 별개다. 답변 이력·처리 메모는 원문과 함께 보관되고 만료 시 함께 제거된다. 발송 결과 불명은 운영 발송 이력 확인이 필요하며 자동 재발송하지 않는다. 전화로 해결했다면 처리 메모와 함께 명시적으로 닫을 수 있다.

## 보관·확인

- 미답변은 연도를 넘어 유지한다. 답변 완료 후 30일이 지나면 일일 `purgeExpiredInquiries` 트리거가 개인정보·질문·답변을 제거한다. 문의 ID/번호·최소 변경 정보는 중복 방지와 삭제 동기화를 위해 유지한다.
- 일반 문의의 처리 항목·보관 기준은 팝업의 동의 상세와 홈페이지 개인정보 안내에 표시한다.
- 기존 견적 알림·번호·주문·재고·판매 기능은 변경하지 않는다. 문의 FCM 알림은 이번 범위에 포함하지 않았다.
- 검증: 홈페이지 프로덕션 빌드, 입력/접수번호 검증, 모의 Apps Script 저장·연도 경계·중복·수정 충돌·메일/문자 상태·개인정보 만료 점검. 실제 Google Sheets 생성/전송, 문자·메일, 모바일 화면 확인은 사용자가 직접 한다.

# 판매 주문 실제 삭제

판매관리의 고객 관리 열기 왼쪽에 삭제 버튼을 제공합니다. 선택한 주문과 삭제 확인이 있어야 실행됩니다.

## 반영 순서

1. 최신 서버의 saleDeletionSync 지원 여부를 확인합니다.
2. 주문번호·revision·같은 삭제요청번호를 PC 전송 대기에 기록합니다. 이 단계에서는 로컬 주문을 지우지 않습니다.
3. 서버 잠금 안에서 revision을 확인하고 판매삭제이력에 PENDING을 기록합니다.
4. 연도별 주문 장부의 월별 탭 및 해당 주문의 호환 저장본에서 행을 삭제합니다.
5. 행 삭제를 다시 확인한 뒤 DONE을 기록하고 성공 응답을 보냅니다.
6. PC는 응답의 주문번호·revision을 확인한 후 로컬 판매 캐시 삭제, 삭제 이력 보존, 전송 대기 해제를 하나의 DB 트랜잭션으로 반영합니다.

전송 중 끊기면 같은 요청으로 재시도합니다. 성공 확인 전에는 로컬 주문을 남깁니다. 삭제 이력은 고객 본문 없이 내부 관리 장부에 보존하며, 같은 주문번호의 재생성과 다음 동기화의 복원을 막습니다. 통계에서도 삭제한 주문이 제외됩니다.

## 배포

기존 운영 Apps Script에 다음 파일을 반영한 후 기존 웹 앱 배포를 새 버전으로 갱신합니다. 운영 URL은 유지합니다.

- Code.gs
- SecureCommerce.gs
- AnnualLedgers.gs

판매삭제이력 시트는 첫 실제 삭제 시 내부 관리 장부에 자동 생성합니다. 주문 장부에는 기존 월별 탭만 유지합니다. 서버 재배포 전에는 새 PC의 삭제 요청이 지원 안내와 함께 중단되며, 삭제 전송 대기나 로컬 삭제를 만들지 않습니다. 삭제 동기화를 받는 다른 PC도 새 소스로 갱신해야 합니다.

## PC 자료와 엑셀 구분

판매관리의 로컬 원본은 DB 캐시입니다. 삭제는 서버 주문 엑셀과 이 캐시에 반영됩니다. 사용자가 따로 내보낸 XLS/엑셀 파일은 경로를 추적하지 않으므로 자동 수정하지 않습니다. 원래 견적요청과 확정견적 장부도 주문 삭제의 대상에 포함하지 않습니다.

이번 변경에서는 사용자 요청에 따라 실행 검사·빌드·운영 데이터 삭제를 수행하지 않았습니다.

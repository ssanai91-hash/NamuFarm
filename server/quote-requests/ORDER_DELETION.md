# 판매 주문 삭제 · 실제 PC 동작 (나피 0.5.5)

**PC 삭제는 이 PC DB에서만 숨김 처리합니다. 서버·Android 원본은 유지하며, 서버 삭제 API는 현재 PC 삭제 버튼에서 사용하지 않습니다.**

## PC 처리 순서

1. 선택 주문번호·revision을 확인하고 사용자 삭제 확인창을 거칩니다.
2. 해당 주문에 `baseFingerprint: None`인 `save_sale` 전송 대기가 있으면 신규 미업로드 판매이므로 삭제를 중단합니다. 먼저 판매관리의 ‘서버에 올리기’를 사용하거나, 주문 취소라면 ‘구매 취소’로 처리합니다.
3. 업로드된 주문은 삭제 전 DB 백업을 생성합니다. 기존 판매에 대한 미전송 수정만 있으면 현재 삭제 확인 흐름을 유지합니다.
4. 이 PC의 판매 캐시에서 주문을 제거하고 해당 주문의 미전송 변경을 제거하며 `hidden_sales`에 주문번호를 보존합니다. 연결된 견적의 입금확인 이력은 보존합니다.
5. 서버에서 다시 가져와도 이 PC가 숨긴 주문을 복원하지 않습니다. 다른 PC와 Android 및 서버 원본은 그대로입니다.

이 PC의 판매 목록과 로컬 집계에서는 숨긴 주문이 제외됩니다. 별도로 내보낸 엑셀 파일은 자동 수정하지 않습니다. 로컬 판매관리 엑셀 사본은 다음 갱신 시 이 PC 자료 기준으로 작성합니다.

## 서버 삭제 API와의 구분

`delete_sale` 서버 API와 내부 `판매삭제이력`은 별도 기능이며 호환성을 위해 남겨 둡니다. 해당 API를 직접 사용하는 클라이언트는 서버 행 삭제와 삭제 이력을 처리하지만, 이를 현재 PC의 삭제 버튼 동작으로 설명해서는 안 됩니다. PC는 옛 버전의 서버 삭제 대기가 있다면 로컬 삭제 처리에서 해당 주문의 대기를 취소합니다. 신규 미업로드 판매 보호 조건을 먼저 적용합니다.

이 설명 정정은 운영 자료를 삭제하거나 서버를 재배포하지 않습니다. 실행·시험·컴파일·실제 고객자료 조작은 수행하지 않았습니다.

# 나피 완성도 보완 · 2026.10.21

PC 나피의 현재 초록색 스타일과 표 구성을 유지하며, 2026.10.21 검토에서 확인한 공간·금액 확인·저장 상태·송장 업무 흐름을 보완했습니다. Android 초기버전 브랜치와 홈페이지는 이번 수정 대상이 아닙니다.

## 견적 작업대

- 품목 제목과 추가·삭제 버튼을 같은 줄에 배치했습니다.
- 창 높이에 맞춰 실제 품목 수 기준으로 최대 8행을 표시합니다. 작은 창에서는 안내 문구와 고객 원문을 기본으로 접어 품목 입력 공간을 우선 확보합니다.
- 고객 원문은 펼치기·접기가 가능합니다. 원문 데이터와 판매자가 입력하는 공식견적서 요청사항은 계속 분리하고, 정사각형 요청사항 입력칸도 유지합니다.
- 확정견적은 기존 품목·택배비 감사 행을 유지하면서, 스크롤 밖 합계 영역에도 묘목금액·선불 택배비 또는 후불·세액을 표시합니다.

## 문자·메일

- 발송 창 상단에 수신인·수신번호 또는 메일주소·견적 총액·택배비 요약을 고정했습니다. 입금확인 문자에도 같은 구조를 적용했습니다.
- 요약은 저장된 견적 기준이며 본문을 직접 수정하면 요약과 금액이 같은지 확인해야 합니다.
- 작은 창에서는 본문과 상태 로그 높이를 조정합니다. 기존 단계별 전송 로그와 성공 확인 조건은 유지합니다.

## 판매·고객관리

- 품목이 적을 때도 강제로 8개의 빈 행을 만들던 부분을 제거했습니다. 큰 창은 최대 8행, 작은 창은 최대 3행 이후 표 안에서 스크롤합니다.
- 주소·송장 입력을 고객 요청정보보다 먼저 배치했습니다. 작은 창에서는 배송 메모와 고객 요청정보를 기본으로 접습니다. 펼치기와 입력값 보존은 유지합니다.

## PC 저장과 서버 반영

- 작업 화면 상단에 PC 저장 상태·서버 반영 대기 건수·이번 실행의 최근 서버 동기화 시각을 표시합니다.
- 서버 전송 실패와 로컬 자료 확인이 필요한 상태를 별도 문구로 안내합니다. 로컬 저장만으로 서버 동기화 성공 시각을 갱신하지 않습니다.
- 로컬 내보내기·가져오기 버튼을 ‘엑셀 파일 저장’·‘엑셀 파일 불러오기’로 바꿔 서버 백업과 구분했습니다.

## 로젠 XLS와 송장 흐름

1. 판매관리에서 수령인·연락처·주소를 입력합니다.
2. ‘주소확인 · 송장 준비’를 눌러 확인한 주소를 저장합니다. 이 단계에는 송장번호가 없어도 됩니다.
3. 배송·송장 목록에서 주문을 선택해 로젠 XLS로 내보냅니다. 기존 SOLD 번호 발급 조건과 계약 운임 입력·중복 내보내기 확인은 유지합니다.
4. 로젠에서 발급받은 송장을 개별 등록하거나 XLS/CSV로 가져옵니다. 확인한 주소가 그대로라면 송장 등록 후 출고 대기로 이어집니다.
5. 실제 배송 후 배송완료 처리합니다. 송장번호와 확인된 배송정보가 모두 필요합니다.

주소·수령인·연락처·송장이 확인 이후 바뀌면 기존 확인 표시는 무효가 됩니다. 주소 확인과 실제 배송완료를 같은 상태로 처리하지 않습니다. 구매확정=입금확인 규칙은 유지합니다.

## 로컬 검증 안내

요청에 따라 Windows 실행·실제 문자/메일·서버 동기화·로젠 업로드·패키지 빌드는 수행하지 않았습니다. 수정 파일의 Python 문법과 패치 형식만 확인했습니다.

사용자 검증 시에는 작은 창과 큰 글씨, 긴 묘목명·비고·8개 이상 품목, 공식견적서 출력, 송장 없는 주문의 XLS 저장과 송장 등록 이후 배송완료 흐름을 확인해주세요. 중복 입금확인·오프라인 저장·백업 복구는 실제 환경 검증 항목으로 남아 있습니다.

## 추가 마감: 입력 보호와 발송 내용 공간

- 판매·고객관리에서 고객정보·주소·송장·메모를 바꾼 뒤 닫기, Esc, 창 X를 누르면 저장하지 않고 닫을지 확인합니다. 기본 선택은 ‘계속 작성’입니다. 조회만 했을 때는 묻지 않습니다.
- 확정견적 표의 순번 열 최소 폭이 실제 폭 계산과 달랐던 부분을 맞춰, 1280×720 검토 조건에서 불필요한 가로 스크롤을 제거했습니다. 묘목명·비고·택배비 행은 유지합니다.
- 문자·메일 창은 모니터 작업영역 높이를 최대한 사용하며, 중복 수신인 정보를 합쳤습니다. 본문이 남는 높이를 모두 사용하고 창 전체 스크롤은 제거했습니다. 본문 자체는 길이에 따라 스크롤합니다. 기존 발송 문구·품목·비고·요청사항을 생략하거나 변경하지 않습니다.
- 금액·택배비 요약과 발송 버튼은 계속 보입니다. 테두리 있는 전송 기록은 최신 상태 위주로 작게 표시하고 ‘전송 기록 펼치기’로 전체 이력을 확인합니다.
- 문자 수신 전화번호는 직접 수정할 수 있으며 하이픈·공백을 제거한 0으로 시작하는 9~11자리 숫자로 검증합니다. 발신번호는 서버 설정을 유지합니다. 수정은 이번 발송 대상에만 적용되며 원래 고객 연락처는 덮어쓰지 않습니다.
- 견적 문자와 입금확인 문자 모두 수정한 수신번호를 실제 요청에 전달하고 발송 기록의 smsTo에도 저장합니다. 원래 견적 내용의 지문과 기존 성공 확인·입금확인 절차는 유지합니다. 전송 중 수신번호는 잠그고, 실패하면 다시 수정할 수 있습니다.

### 확인한 범위

가상 자료로 변경된 Qt 화면을 확인하고, 입력 취소 보호·표 폭·본문 공간·전화번호 검증·수정 번호 전달·입금확인 성공 조건을 확인하는 좁은 회귀 검사를 추가했습니다. 실제 문자/메일 발송, 운영 서버 연동, Windows 글꼴/배율, 실행파일 빌드는 수행하지 않았습니다.

## 규격 입력 및 발송 전 작성중 저장

- 견적 작업대·확정견적 품목표는 순번 / 묘목명 / 규격 / 수량 / 판매단가 / 판매금액 순서입니다. 기존 비고 입력칸을 규격 입력칸으로 바꿨습니다. 규격은 공식견적서의 규격 칸, 문자·메일·입금확인 안내, 판매 등록 데이터에 반영됩니다.
- 기존 비고만 있는 품목은 규격 입력칸에서 이어서 수정할 수 있습니다. 저장할 때 기존 비고는 legacyRemarks에 보존하고 현재 입력은 specification으로 저장합니다. 이미 확정한 원본은 열어보기만 해서는 변경하지 않습니다.
- 작업대 하단에 ‘작성중 저장’을 추가했습니다. 창을 닫지 않고 이 PC의 DB에 저장합니다. 입력이 덜 끝난 고객정보·빈 품목·수량도 초안으로 보관하며, 실제 발송과 완료에는 기존 필수값 검사를 적용합니다.
- 작성중 견적은 기존 견적 목록에 ‘작성중’ 상태로 표시됩니다. 목록 이름은 ‘견적 작업대’로 정리하고 선택하면 ‘이어서 작성’으로 편집합니다. 홈페이지 요청에서도 같은 요청의 저장한 초안을 다시 엽니다. 기존 초안 보관 기간과 로컬 저장 정책을 사용하며, 작성중 저장은 서버 상태를 변경하거나 문자를 보내지 않습니다.
- 견적완료와 작성중 저장은 별도입니다. 현재 내용의 문자 또는 메일 전달 성공을 확인해야 완료할 수 있습니다. 확정 저장이 끝나면 같은 초안은 작성중 목록에서 정리합니다.
- 저장 실패 시 수정 내용과 미저장 상태를 유지합니다. 작성중 초안 삭제는 로컬 초안만 삭제합니다.
- 가상 DB 재열기, 미완성 수기 견적 저장, 규격 출력 연결, 초안 이어쓰기와 완료 구분 등을 포함한 좁은 회귀 검사 14개를 통과했습니다. 운영 발송·서버 동기화·Windows 빌드는 수행하지 않았습니다.

## 노트북 150% 배율 대응

- Windows 1920×1200, 150%에서는 논리 작업공간이 약 1280×800입니다. 창 너비 1440 미만 또는 높이 850 미만이면 메뉴·요약 영역·글자·버튼 여백과 목록 행 높이를 자동으로 줄입니다. 넓은 창에서는 기존 크기로 돌아오며 ‘큰 글씨로 보기’ 선택은 유지합니다.
- 견적요청·견적 작업대·판매관리 목록의 최소 열 폭을 조정했습니다. 기존 업무 열은 유지합니다. 더 좁은 창에서는 판매관리 검색과 자료 전송 버튼을 두 줄로 배치합니다.
- 견적 작성·확인·고객관리 팝업은 작은 창에서 글자와 버튼 크기를 조정합니다. 견적 품목 행은 기본 36px로 줄이고, 규격 입력·단가 조절·합계·작성중 저장과 발송 버튼을 유지합니다. 왼쪽의 정사각 요청사항 입력란은 스크롤로 접근할 수 있습니다.
- 아이콘에 150%·200%·300%용 렌더링을 제공하고, Windows 패키징에는 PerMonitorV2 매니페스트를 명시합니다. 로컬 배치 파일과 두 Windows 빌드 워크플로에 동일하게 반영했습니다. Windows 배율을 강제로 낮추거나 화면 전체를 축소하지 않습니다.
- 변경 관련 회귀 검사 18개를 통과했습니다. 별도 프로세스에서 QT_SCALE_FACTOR=1.5로 노트북 배치 검사 4개를 통과했고, 1280×740 및 1240×740 화면을 캡처해 주요 목록의 가로 스크롤과 버튼 위치를 확인했습니다.
- 기존 test_workspace는 현재 소스에 없는 ManualQuoteDialog를 가져오려 하여 실행되지 않았고, test_ui는 이 작업용 소스 사본에 서버 fixture가 없어 시작되지 않았습니다. 전체 통합검사 통과로 보고하지 않습니다. Windows 실행파일 빌드 및 실제 노트북 글꼴 선명도는 로컬에서 확인해야 합니다.

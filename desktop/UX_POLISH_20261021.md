# 나피 완성도 보완 · 2026.10.21

PC 나피의 현재 초록색 스타일과 표 구성을 유지하며, 2026.10.21 검토에서 확인한 공간·금액 확인·저장 상태·송장 업무 흐름을 보완했습니다. Android 초기버전 브랜치와 홈페이지는 이번 수정 대상이 아닙니다.

## 견적 작업대

- 품목 제목과 추가·삭제 버튼을 같은 줄에 배치했습니다.
- 창 높이에 맞춰 실제 품목 수 기준으로 최대 8행을 표시합니다. 작은 창에서는 안내 문구와 고객 원문을 기본으로 접어 품목 입력 공간을 우선 확보합니다.
- 고객 원문은 펼치기·접기가 가능합니다. 원문 데이터와 판매자가 입력하는 공식견적서 요청사항은 계속 분리하고, 정사각형 요청사항 입력칸도 유지합니다.
- 확정견적은 기존 품목·택배비 감사 행을 유지하면서, 스크롤 밖 합계 영역에도 묘목금액·선불 택배비 또는 후불·세액을 표시합니다.

## 문자·메일

- 발송 창 상단에 수신인·수신번호 또는 메일주소·견적 총액·택배비 요약을 고정했습니다. 입금확인 문자에도 같은 구조를 적용했습니다.
- 요약은 저장된 견적 기준이며 본문을 직접 수정하면 요약과 금액이 같은지 확인해야 합니다.
- 작은 창에서는 본문과 상태 로그 높이를 조정합니다. 기존 단계별 전송 로그와 성공 확인 조건은 유지합니다.

## 판매·고객관리

- 품목이 적을 때도 강제로 8개의 빈 행을 만들던 부분을 제거했습니다. 큰 창은 최대 8행, 작은 창은 최대 3행 이후 표 안에서 스크롤합니다.
- 주소·송장 입력을 고객 요청정보보다 먼저 배치했습니다. 작은 창에서는 배송 메모와 고객 요청정보를 기본으로 접습니다. 펼치기와 입력값 보존은 유지합니다.

## PC 저장과 서버 반영

- 작업 화면 상단에 PC 저장 상태·서버 반영 대기 건수·이번 실행의 최근 서버 동기화 시각을 표시합니다.
- 서버 전송 실패와 로컬 자료 확인이 필요한 상태를 별도 문구로 안내합니다. 로컬 저장만으로 서버 동기화 성공 시각을 갱신하지 않습니다.
- 로컬 내보내기·가져오기 버튼을 ‘엑셀 파일 저장’·‘엑셀 파일 불러오기’로 바꿔 서버 백업과 구분했습니다.

## 로젠 XLS와 송장 흐름

1. 판매관리에서 수령인·연락처·주소를 입력합니다.
2. ‘주소확인 · 송장 준비’를 눌러 확인한 주소를 저장합니다. 이 단계에는 송장번호가 없어도 됩니다.
3. 배송·송장 목록에서 주문을 선택해 로젠 XLS로 내보냅니다. 기존 SOLD 번호 발급 조건과 계약 운임 입력·중복 내보내기 확인은 유지합니다.
4. 로젠에서 발급받은 송장을 개별 등록하거나 XLS/CSV로 가져옵니다. 확인한 주소가 그대로라면 송장 등록 후 출고 대기로 이어집니다.
5. 실제 배송 후 배송완료 처리합니다. 송장번호와 확인된 배송정보가 모두 필요합니다.

주소·수령인·연락처·송장이 확인 이후 바뀌면 기존 확인 표시는 무효가 됩니다. 주소 확인과 실제 배송완료를 같은 상태로 처리하지 않습니다. 구매확정=입금확인 규칙은 유지합니다.

## 로컬 검증 안내

요청에 따라 Windows 실행·실제 문자/메일·서버 동기화·로젠 업로드·패키지 빌드는 수행하지 않았습니다. 수정 파일의 Python 문법과 패치 형식만 확인했습니다.

사용자 검증 시에는 작은 창과 큰 글씨, 긴 묘목명·비고·8개 이상 품목, 공식견적서 출력, 송장 없는 주문의 XLS 저장과 송장 등록 이후 배송완료 흐름을 확인해주세요. 중복 입금확인·오프라인 저장·백업 복구는 실제 환경 검증 항목으로 남아 있습니다.

# 나무팜 PC 관리 프로그램

Python 3.11 이상 + PySide6(Qt)를 사용합니다. 홈페이지 요청과 앱에서 구매 확정한 판매 기록을 기존 Apps Script API와 같은 구글시트에서 읽고 관리합니다.

## 실행

Windows에서는 이 브랜치를 내려받고 `desktop/start_windows.bat`를 실행합니다. 첫 실행은 Python 3.11 이상과 인터넷 연결이 필요하며, 필요한 패키지를 자동 설치합니다. 설치 후에는 오프라인으로 보관함을 열 수 있습니다.

Windows 실행 파일은 GitHub Actions **Desktop manager CI → NamuFarm-PC-Windows** 아티팩트에서 내려받습니다. 직접 빌드하려면 `desktop/build_windows.bat`를 실행합니다. 실행 파일은 `desktop/dist/NamuFarm-PC.exe`에 생성됩니다.

다른 OS에서는 저장소 루트에서:

```sh
python -m pip install -e desktop
python -m namufarm_desktop
```

## 처음 연결하기

1. 휴대폰 나무팜 앱에서 **보안 백업 저장**과 **서버 보안 연결**을 완료합니다. PC는 새 보안키를 만들지 않고 이 백업키를 가져옵니다.
2. Apps Script 프로젝트의 `Code.gs`, `SecureCommerce.gs`를 이 브랜치의 `server/quote-requests/` 파일로 업데이트합니다. 기존 배포의 새 버전을 만들고 기존 `/exec` URL·실행 주체·접근 설정을 유지합니다. 데이터 시트는 새로 만들거나 비우지 않습니다.
3. 공개 GET 응답에서 `version: 4`, `requestDeletionSync: true`, `encryptionReady: true`를 확인합니다. 이전 v4 배포에는 삭제 변경 전달과 JSON 순서 호환성 보완이 없으므로 PC가 동기화를 차단합니다.
4. PC 첫 화면에서 앱 백업 JSON, 앱 백업 비밀번호, 새 PC 보관함 비밀번호(12자 이상)를 입력합니다. 서버 URL 기본값은 기존 요청함 URL입니다.
5. Apps Script 소유자로 `createDeviceInvite()`를 실행해 **PC용 새 일회용 연결 코드**를 발급합니다. 휴대폰에 이미 사용한 코드를 재사용하지 않습니다.
6. PC **연결·설정** 탭에서 연결 코드를 입력하고 **PC 연결하고 처음 동기화**를 누릅니다. 키가 다른 서버에는 연결하지 않습니다.

## 화면과 동작

| 화면 | 기능 |
| --- | --- |
| 견적 요청 | 고객·연락처·묘목·지역 검색, 상세 조회, 문의 삭제 |
| 판매 관리 | 고객·배송 정보, 원가·비용, 매입판매/중개수수료 방식 수정 및 저장 |
| 판매 단계 | 구매확정 → 입금확인 → 배송확인 → 판매완료. 실제 입금·배송 확인과 완료 전 원가 확인 필요 |
| 일·월·년 통계 | 한국 시간 판매완료일 기준 수량·매출·세액·원가·비용·매출이익 조회 |
| 연결·설정 | 보관함 잠금 해제, PC 연결, 60초 자동 동기화, 전송 대기와 수정 충돌 확인 |

홈페이지 문의만으로 주문·재고 차감은 발생하지 않습니다. 견적 발행·신규 구매 확정·재고 관리·배송 전 주문 취소는 기존 휴대폰 앱에서 처리합니다. PC는 이미 구매 확정한 판매를 관리합니다. 완료·취소된 판매는 수정하지 않습니다. 발행 견적의 전화번호와 판매 품목·수량·매출 원본은 유지합니다.

PC 저장은 암호화 보관함과 전송 대기를 한 SQLite transaction으로 기록합니다. 서버 응답까지 검증한 뒤에만 전송 대기를 지우고 최신 기록을 읽습니다. 연결이 끊기거나 응답이 유실되면 같은 변경번호로 재시도합니다. 전송 대기 중에는 추가 수정이 잠깁니다. 수정 중에는 자동 동기화가 입력내용을 덮어쓰지 않습니다.

다른 휴대폰/PC가 같은 판매를 먼저 수정하면 충돌을 표시합니다. **수정 충돌 확인**에서 PC 입력과 서버 최신값을 비교한 뒤 **PC 수정 버리고 서버 기록 사용**을 선택할 수 있습니다. 서버 값이 다시 바뀌면 대기를 버리지 않고 재확인을 요구합니다.

문의 삭제는 고객 암호문을 제거하고 새 변경순번을 부여합니다. 휴대폰은 다음 **요청함 동기화**에서 문의와 연결된 미구매 견적 사본을 제거합니다. 구매한 판매 기록은 유지합니다. 즉시 푸시로 휴대폰 화면을 강제 변경하는 방식은 아닙니다.

## 보관함

보관함은 Qt의 사용자별 앱 데이터 폴더 안 `namufarm-vault.db`입니다. 정확한 경로는 연결·설정 화면에 표시됩니다. Windows 기본 경로는 `%LOCALAPPDATA%\NamuFarm\NamuFarmDesktop\namufarm-vault.db`입니다.

고객정보·개인키·기기 토큰·전송 대기를 AES-256-GCM으로 저장하고, PC 비밀번호에서 PBKDF2-HMAC-SHA256(1,300,000회)로 보관함 키를 유도합니다. 앱 백업은 기존 PBKDF2-HMAC-SHA1 형식을 그대로 읽으며 네트워크 전송은 기존 RSA-OAEP SHA256 + AES-256-GCM을 사용합니다. 잠금 상태에서는 고객정보 화면을 비웁니다.

PC 보관함 백업은 프로그램을 닫고 DB 파일을 복사합니다. 비밀번호는 복구할 수 없으므로 보관해야 합니다. DB가 손실되면 앱 보안 백업으로 새 PC 연결은 가능하지만 서버에 아직 전송하지 못한 수정은 복구되지 않습니다. 미구매 문의 30일·종료 판매 5년 보관 종료 규칙을 따르며, 오래된 서버 순번·누락된 판매·삭제 문의 재등장은 기존 캐시를 덮어쓰지 않습니다.

## 검증

```sh
QT_QPA_PLATFORM=offscreen python -m unittest discover -s desktop/tests -v
node --test server/quote-requests/tests/*.test.cjs
```

PC 테스트는 실제 Apps Script 소스를 메모리 시트에서 실행해 키 백업/암호화 호환, 저장·단계 진행·통계, 응답 유실·재시도·동시 수정·변조·DB rollback 및 Qt 버튼 동작을 확인합니다. 실제 계정·운영 시트·실제 고객 데이터는 테스트에 사용하지 않습니다. Android 회귀 테스트에는 이미 받은 문의의 PC 삭제 전달 검증을 포함합니다.

Windows CI는 같은 테스트 후 PyInstaller 실행 파일을 빌드합니다. 실사용 PC의 설치·파일 선택과 실제 휴대폰/시트 왕복 동기화는 운영 설정 후 확인해야 합니다.

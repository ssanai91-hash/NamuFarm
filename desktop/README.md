# 나무팜 PC 판매관리 0.4.9

Windows에서 견적 접수·작성, 입금확인, 배송완료, 로젠 송장번호, 매출·이익을 관리합니다. Google Sheets API v5와 기기 인증을 사용합니다. 연결파일을 처음 한 번 선택하면 됩니다. 별도 키 입력·복호화 백업·새 비밀번호 설정이 필요 없습니다.

## 실행

- 실행 파일: GitHub Actions **Desktop manager CI → NamuFarm-PC-Windows**의 `NamuFarm-PC.exe`. Python 설치 없이 실행합니다.
- 소스로 실행: Python 3.11 이상을 설치하고 `start_windows.bat`. 최초 실행 시 PySide6·cryptography·XLS 입출력 패키지를 설치합니다.
- 읽기 전용 화면 보기: `NamuFarm-PC.exe --demo` 또는 `preview_windows.bat`. 예시 데이터만 표시하고 운영 서버·보관함에 접근하지 않습니다.
- 실행 파일 빌드: `build_windows.bat` → `dist/NamuFarm-PC.exe`.

FHD 1920×1080 기준으로 최대화해서 시작합니다. Windows 125% 배율에 해당하는 1536×864 논리 크기에서도 목록과 고정 저장 버튼을 사용할 수 있습니다. 네트워크·암호화 작업은 별도 작업 스레드에서 실행합니다.

## 처음 연결

1. 프로그램을 실행하면 Windows 계정으로 보호되는 로컬 자료를 자동으로 엽니다.
2. 최초 한 번만 `연결파일 불러오기`에서 `나무팜-연결.json`을 선택합니다.
3. 연결 정보와 기기 인증은 이 PC에 보호 저장되므로 다음 실행부터 연결파일을 다시 고를 필요가 없습니다.
4. 이후 `지금 동기화`를 누르면 Google Sheet의 최신 견적요청을 로컬 캐시에 내려받고 `나무팜-견적요청.xlsx` 조회용 사본도 갱신합니다.

Google Sheet가 서버 원본입니다. PC의 SQLite는 안전한 로컬 캐시이고 XLSX는 사람이 보기 위한 조회용 사본입니다. XLSX 두 파일을 서로 양방향 동기화하면 충돌·파일잠금·중복저장 판단이 불안정해지므로 사용하지 않습니다.

서버 배포와 연결파일 생성은 [로컬 동기화 안내](../docs/LOCAL_SHEET_SYNC.md)를 확인합니다. 기존 일회용 연결코드는 접힌 ‘이전 연결코드 방식 표시’에서 계속 사용할 수 있습니다.

기존 비밀번호 방식의 PC 보관함은 처음 한 번 기존 비밀번호를 입력하면 자동 연결 방식으로 전환합니다. 토큰·초안·전송 대기는 그대로 보존합니다. 기존 암호화 자료에 대한 안내가 있을 때만 ‘이전 자료 복원’으로 이전 JSON을 가져옵니다. 새 자료에는 사용하지 않습니다.

Windows 계정이나 PC를 바꾸면 새로 기기 인증하고 서버에 동기화된 기록을 가져옵니다. 로컬 초안·미전송 내역은 자동으로 다른 PC에 복구되지 않습니다. DB 파일만 복사해 다른 Windows 계정에서 여는 방식은 지원하지 않습니다.

운영 API는 기본 입력되어 있습니다:

```
https://script.google.com/macros/s/AKfycbw4GnfIlXyjMo9TPZmCmRnmIIzd016piTDma-xrh7w/exec
```

현재 서버는 복구된 비공개 관리 시트에 연결한 API v5입니다. `Code.gs + SecureCommerce.gs + MonthlyStorage.gs + RecoverySetup.gs` 소스를 사용합니다. 삭제된 서버를 사용하던 PC는 최초 한 번 연결파일을 불러와야 하며 초안과 미전송 내역은 유지합니다. 연도별 견적·주문 분리를 사용하려면 `AnnualLedgers.gs`를 함께 적용하고 [연도별 장부 안내](../docs/ANNUAL_QUOTE_ORDER_LEDGERS.md)의 초기화를 실행합니다. 서버가 월별 탭을 관리하고 PC는 통합 조회합니다. 자세한 운영 정보는 `docs/GOOGLE_SERVER_RECOVERY_20261009.md`를 확인합니다.

## 견적에서 판매로

1. 요청을 선택하거나 `새 견적`에서 고객·품목·단가를 입력합니다.
2. `초안 저장`은 이 PC의 암호화 보관함에 저장합니다. **초안은 다른 기기·시트에 공유되지 않고 30일 뒤 제거됩니다.** 앱에서 상담 종료한 문의의 연결 초안은 제거됩니다. 시트에서 행만 지운 경우 로컬 초안은 유지되지만 해당 문의로 구매 확정할 수는 없습니다.
3. `견적안 미리보기 / PDF`로 전달할 문서를 만듭니다. 문자·이메일 자동 발송은 하지 않습니다.
4. 고객 구매 의사를 확인하고 `입금확인 → 판매 등록`을 누릅니다. 확정 품목·금액·견적서 원본을 인증된 HTTPS API로 입금확인월의 주문 장부에 저장합니다. 연결 견적은 발송완료 상태로 유지합니다. 판매 관리에서 확정 견적서를 재출력할 수 있습니다.
5. 구매 확정은 입금확인으로 동일 처리합니다. 이후 배송완료 또는 구매취소로 처리합니다. 확정 품목·수량·금액은 수정할 수 없습니다.

PC 작성 품목은 기존 Android의 `수기견적` 형식입니다. **휴대폰 재고를 차감하지 않습니다.** 재고 기반 판매·재고 변경·주문 취소는 현재 Android 업무 범위입니다. 연도별 장부 모드에서는 같은 접수의 중복 주문 생성을 서버에서 차단합니다. 오프라인 변경은 로컬 전송 대기에 남고, 기존 주문과 충돌하면 서버 기록을 확인해 채택할 수 있습니다.

## 로젠 송장 업무 (.xls)

2026-10-08에 제공받은 **로젠택배 대량발송 송장엑셀.xls**의 첫 시트 `제목없음(주소만있음)`을 기준으로 합니다. 실제 Excel 97-2003 **BIFF8 .xls**로 저장합니다. XLSX나 CSV의 확장자를 바꾼 파일이 아닙니다. 원본 고객 예시·발송인·운임 값은 프로그램이나 저장소에 복사하지 않습니다.

1. 판매 관리에서 **입금확인**, 수령인·연락처·5자리 우편번호·배송주소를 확인합니다.
2. `배송 · 로젠 송장`에서 한 건 또는 여러 건을 선택합니다. 현재 검색·필터 결과는 `목록 전체 선택`으로 선택할 수 있습니다.
3. **선택 주문 로젠 XLS 저장**을 누릅니다. 서버에서 최신 상태를 다시 확인하며 미입금·주소 누락·배송 진행/완료 주문은 차단합니다. 이미 송장이 있거나 이 PC에서 최근 30일 이내 내보낸 주문은 재출고 확인을 받습니다.
4. 발송인과 실제 출고지, 주문별 **박스 수**, **계약 운임 합계**, **선착불 코드**를 확인합니다. 박스 수 초깃값은 1이며 묘목 수량과 무관합니다. 운임과 코드는 자동 추정하지 않으며 반드시 입력해야 합니다. 공통 운임·코드는 전체 적용 후 개별 수정할 수 있습니다. 무료 운임은 0을 직접 입력합니다.
5. XLS를 저장하고 로젠의 엑셀 불러오기에서 **첫 시트 `제목없음(주소만있음)` / 시작 행 2 / A~X열**을 선택합니다. 시트 이름에 '제목없음'이 있지만 첨부 원본과 출력 파일 모두 1행은 제목입니다. 첫 주문은 2행입니다.
6. 로젠에서 주소·계약운임·포장을 검증한 뒤 **개별 또는 일괄 공식 송장 출력**을 진행합니다. XLS 저장만으로 택배 접수·송장 발급·배송완료 처리되지는 않습니다.
7. 발급 후 XLS의 **주문대조표** 시트에 실제 송장번호를 **텍스트로** 채워 원본 XLS 형식으로 저장하고 `송장 XLS / CSV 가져오기`를 누릅니다. 또는 `주문번호,송장번호` 두 열의 CSV를 가져옵니다. 주문대조표의 주문번호와 첫 시트의 출고자료 행번호를 함께 보며 대조합니다. 로젠에서 행을 재정렬했다면 수령인·전화도 확인해야 합니다.

### 원본 열 매핑

| 열 | 제목 | 입력값 |
|---|---|---|
| A | 수화주명 | 수령인 |
| B | 우편 | 우편번호(텍스트) |
| C | 주소 | 도로명주소 + 상세주소 |
| D / E | 전화 / 휴대폰 | 주문 연락처 / 휴대폰 번호인 경우 동일 번호 |
| F | 택배수량 | 확인한 박스 수 |
| G | 운임 | 확인한 계약 운임 합계 |
| H | 선착불 | 사용자가 확인한 원시 코드(텍스트) |
| I | 물품명 | 주문 품목명과 묘목 수량 |
| J | 공란 | 공란 유지 |
| K | 배송메세지 | 기존 송장 표시를 제외한 고객 메모 |
| L~R | 공란 | 공란 유지 |
| S~V | 송하인명 / 주소 / 전화 / 핸드폰번호 | 확인한 발송인 정보 |
| W | 공란 | 공란 유지 |
| X | 제주선착불 | 사용자가 확인한 코드, 미사용 시 공란 |

원본 첫 시트의 선착불 예시는 `1`, 다른 예시 시트에는 `010`이 들어 있습니다. **두 값을 같은 뜻으로 추정하거나 고객 견적의 선불/착불 값을 변환하지 않습니다.** 계약 로젠 프로그램에서 사용하는 코드를 그대로 입력합니다. 계정별 코드 의미와 택배수량 해석은 최초 업로드 때 확인해야 합니다. 발송인 기본값은 나무팜의 기존 발행자 설정이며 최초 저장 전 실제 출고지로 확인·수정합니다. 저장에 성공하면 발송인과 최근 내보내기 이력만 PC 보관함에 암호화해 기억합니다. 이 이력은 다른 PC/Android와 공유되지 않습니다.

송장 가져오기는 최대 500건/2MB입니다. XLS는 `주문번호`와 `송장번호` 제목이 있는 시트 하나를 사용하며, CSV는 UTF-8 BOM 또는 CP949를 지원합니다. 번호가 비어 있는 주문은 채우거나 가져올 시트에서 제거하세요. 파일 전체 검증 후 미리보기를 보여주며 없는 주문·중복 주문·중복 송장·기존 번호와 다른 값은 차단합니다. 일부 저장 후 실패하면 완료 건수와 재시도 안내를 표시합니다. 동기화 후 동일한 파일로 재시도하면 같은 번호는 건너뜁니다.

송장은 기존 암호화 `order.note`의 `[로젠택배 송장] 11자리번호` 한 줄에 보관합니다. 기존 Android와 호환되며 고객 메모도 유지합니다. 휴대폰에서 메모 전체를 지우면 번호도 지워지므로 이 줄을 유지하세요. 입금확인·배송확인 상태에서 등록/수정하며 배송완료 기록은 수정하지 않습니다.

`송장번호 · 출고 확인서 출력`은 A4 확인서이며 택배 부착용 라벨은 로젠에서 출력합니다. 나무팜에는 현재 **주문당 대표 송장 1개**만 저장합니다. 복수 박스의 개별 송장은 로젠에서 관리·확인합니다. Open API 연동은 사용하지 않습니다.

## 보관과 동기화

- PC SQLite는 AES-256-GCM으로 보호하며 저장 키는 Windows 현재 사용자 DPAPI로 자동 관리합니다. 이전 비밀번호 보관함·RSA 암호문 읽기는 호환 목적으로 남깁니다. API v5 전송은 기기 인증된 HTTPS를 사용합니다.
- 정확한 보관함 위치는 연결·설정에 표시합니다. 종료 후 `namufarm-vault.db`를 복사하면 보관함·초안을 백업할 수 있습니다.
- 판매 수정과 전송 대기는 같은 트랜잭션에 보관합니다. 서버 저장 응답이 일치할 때만 대기를 지웁니다. 응답 유실 시 같은 이벤트 ID로 재전송합니다.
- 미전송 변경이 있으면 추가 수정을 막습니다. 다른 기기와 충돌하면 비교 화면에서 최신 서버 버전을 선택합니다.
- 입력 중에는 자동 동기화를 멈춥니다. 잠그면 화면의 고객·배송·초안 정보를 지웁니다. 문의 30일, 완료/취소 판매 5년의 기존 보관 규칙을 따릅니다.
- 내보낸 XLS·PDF·CSV는 일반 문서입니다. 고객정보가 불필요해지면 삭제하고 발송·송장 내용을 로젠 시스템에서도 확인하세요.

실제 Apps Script 소스를 메모리 시트 fixture에서 실행하며 테스트 고객·키만 사용합니다. 운영 시트에 테스트 주문을 넣지 않습니다. GitHub CI는 Linux 테스트 후 Windows에서도 검사하고 실행 파일을 만들며 패키지 시작을 확인합니다.

설계 참고: [카페24 주문·배송 관리](https://www.cafe24.com/commerce/manage/order.html)의 상태별 업무·일괄 송장 입력, [로젠 공식 조회](https://www.ilogen.com/web/personal/tkSearch?t=1)의 11자리 송장 안내. 화면과 코드는 나무팜 업무에 맞게 별도로 작성했습니다.




### 전화 수기견적

온라인 견적요청 화면의 `전화 견적 추가` 또는 상단 `+ 전화 견적`에서 고객명·전화번호를 기본으로 입력하고, 이메일·지역·요청사항은 선택으로 유지합니다. 묘목명·수량·판매단가는 직접 입력하며 판매금액은 자동 계산합니다. 전화 견적은 `M-YYYYMMDD-HHMMSS-XXXX` 형식의 표시용 번호와 별도 UUID 내부 식별자를 사용하고, 추가 즉시 견적 작업대의 `견적확정` 상태로 들어갑니다.

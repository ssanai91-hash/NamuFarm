# 나무팜 PC 판매관리 0.2

Windows에서 견적 접수·작성, 구매 확정, 입금·배송 확인, 로젠 송장번호, 매출·이익을 관리합니다. 기존 운영 Google Sheets API v4와 판매자 암호화 키를 사용합니다.

## 실행

- 실행 파일: GitHub Actions **Desktop manager CI → NamuFarm-PC-Windows**의 `NamuFarm-PC.exe`. Python 설치 없이 실행합니다.
- 소스로 실행: Python 3.11 이상을 설치하고 `start_windows.bat`. 최초 실행 시 PySide6·cryptography를 설치합니다.
- 읽기 전용 화면 보기: `NamuFarm-PC.exe --demo` 또는 `preview_windows.bat`. 예시 데이터만 표시하고 운영 서버·보관함에 접근하지 않습니다.
- 실행 파일 빌드: `build_windows.bat` → `dist/NamuFarm-PC.exe`.

FHD 1920×1080 기준으로 최대화해서 시작합니다. Windows 125% 배율에 해당하는 1536×864 논리 크기에서도 목록과 고정 저장 버튼을 사용할 수 있습니다. 네트워크·암호화 작업은 별도 작업 스레드에서 실행합니다.

## 처음 연결

1. 휴대폰 나무팜에서 기존 **판매자 보안 백업 JSON**을 내보냅니다.
2. PC `연결 · 설정 → 보관함 열기 / 처음 설정`에서 백업과 백업 비밀번호를 입력합니다.
3. PC 보관함 비밀번호를 12자 이상으로 정합니다.
4. 운영 Apps Script에서 소유자가 `createDeviceInvite()`를 실행한 PC용 일회용 연결 코드를 입력합니다.
5. `PC 연결하고 처음 동기화`를 누릅니다. 서버 공개키와 백업 키가 일치해야 연결됩니다.

기존 키를 새로 만들거나 교체하지 않습니다. Google Cloud OAuth 게시와 각 PC의 기기 연결은 별개입니다. 키·비밀번호·연결 코드를 채팅이나 저장소에 올리지 마세요.

운영 API는 기본 입력되어 있습니다:

```
https://script.google.com/macros/s/AKfycbw8uqBWveIhqmXielALjSLnY1yDenKAwl070FT6Lsxsj7Xiod1C5JSBDZGfQtlrl6A-CQ/exec
```

현재 서버는 독립형 `Code.gs + SecureCommerce.gs + MonthlyStorage.gs` 배포입니다. 이번 PC 버전 때문에 서버 재배포나 운영 시트 재생성은 필요하지 않습니다. 월별·일별 요청 시트는 서버가 관리하고 PC는 통합 조회합니다.

## 견적에서 판매로

1. 요청을 선택하거나 `새 견적`에서 고객·품목·단가를 입력합니다.
2. `초안 저장`은 이 PC의 암호화 보관함에 저장합니다. **초안은 다른 기기·시트에 공유되지 않고 30일 뒤 제거됩니다.** 원래 문의가 서버에서 삭제되면 연결 초안도 동기화 시 제거됩니다.
3. `견적안 미리보기 / PDF`로 전달할 문서를 만듭니다. 문자·이메일 자동 발송은 하지 않습니다.
4. 고객 구매 의사를 확인하고 `구매 확정 → 판매 등록`을 누릅니다. 확정 품목·금액·견적서 원본을 암호화해 운영 판매 시트에 저장하고 연결 요청을 마감합니다. 판매 관리에서 확정 견적서를 재출력할 수 있습니다.
5. 구매 확정과 입금 확인은 별도입니다. 실제 입금 후 다음 상태로 진행합니다. 확정 품목·수량·금액은 수정할 수 없습니다.

PC 작성 품목은 기존 Android의 `수기견적` 형식입니다. **휴대폰 재고를 차감하지 않습니다.** 재고 기반 판매·재고 변경·주문 취소는 현재 Android 업무 범위입니다. 같은 접수를 PC와 휴대폰에서 동시에 신규 구매 확정하지 마세요. PC는 확정 직전에 서버를 확인하지만 기존 API에는 기기 간 신규 주문의 접수별 예약 기능이 없습니다.

## 로젠 송장 업무

1. 판매 관리에서 입금 확인과 수령인·전화·5자리 우편번호·주소를 입력합니다.
2. 배송 화면에서 선택 주문의 `출고 CSV`를 저장합니다. 주소 누락·미입금 주문은 차단합니다. 송장이 있는 주문을 다시 내보낼 때 재출고 여부를 확인합니다.
3. **Excel → 데이터 → 텍스트/CSV에서** 가져오고 주문번호·수하인전화·우편번호·송장번호는 텍스트 열로 지정해 앞자리 0을 보존합니다. 단순 더블클릭하면 Excel이 앞자리 0을 지울 수 있습니다.
4. 계약 로젠 프로그램의 Excel 형식으로 저장하고 열을 매핑합니다. 발송인, 박스 수, 포장 규격, 계약 운임은 로젠에서 확인합니다. CSV `수량`은 **묘목 수량이며 박스 수가 아닙니다**. `운임구분`은 고객 견적의 선불/착불 정보이며 계약 운임 코드가 아닙니다.
5. **로젠에서 실제 송장번호를 발급하고 택배 부착용 공식 운송장을 출력합니다.**
6. 실제 번호를 PC에 입력하거나 `주문번호,송장번호` 두 열의 CSV로 가져옵니다. 주문번호는 출고 CSV의 원본 값을 그대로 사용합니다.

CSV는 최대 500건/2MB, UTF-8 BOM 또는 CP949를 지원합니다. 전체 파일 검증 후 미리보기를 보여주며 없는 주문·중복 주문·중복 번호·기존 번호와 다른 값은 차단합니다. 일부 저장 후 실패하면 완료 건수와 재시도 안내를 표시합니다. 동기화 후 같은 CSV로 재시도하면 같은 번호는 건너뜁니다.

송장은 기존 `order.note`의 `[로젠택배 송장] 11자리번호` 한 줄에 보관합니다. 기존 Android가 모르는 필드를 수정 시 없애지 않도록 기존 암호화 필드를 사용했습니다. 고객 메모는 유지하며 휴대폰에서도 번호를 볼 수 있습니다. 메모 전체를 지우면 번호도 지워지므로 이 줄을 유지하세요. 입금확인·배송확인 상태에서 등록/수정하며 판매완료 기록은 수정하지 않습니다.

`송장번호 · 출고 확인서 출력`은 번호·수령인·주소·품목·포장 확인란을 담은 A4 PDF/인쇄 문서입니다. **택배 부착용 공식 운송장이나 바코드 라벨이 아닙니다.** 번호 등록으로 배송완료를 자동 처리하지 않습니다. 한 주문의 복수 박스·복수 송장은 이번 버전 범위에 포함되지 않습니다.

## 보관과 동기화

- PC SQLite는 AES-256-GCM 및 PBKDF2-HMAC-SHA256 1,300,000회로 보호합니다. 기존 Android 보안 백업을 읽고 API에는 RSA-OAEP-SHA256/AES-GCM 암호문을 전송합니다.
- 정확한 보관함 위치는 연결·설정에 표시합니다. 종료 후 `namufarm-vault.db`를 복사하면 보관함·초안을 백업할 수 있습니다.
- 판매 수정과 전송 대기는 같은 트랜잭션에 보관합니다. 서버 저장 응답이 일치할 때만 대기를 지웁니다. 응답 유실 시 같은 이벤트 ID로 재전송합니다.
- 미전송 변경이 있으면 추가 수정을 막습니다. 다른 기기와 충돌하면 비교 화면에서 최신 서버 버전을 선택합니다.
- 입력 중에는 자동 동기화를 멈춥니다. 잠그면 화면의 고객·배송·초안 정보를 지웁니다. 문의 30일, 완료/취소 판매 5년의 기존 보관 규칙을 따릅니다.
- 내보낸 PDF·CSV는 일반 문서입니다. 고객정보가 불필요해지면 삭제하고 발송·송장 내용을 로젠 시스템에서도 확인하세요.

## 개발·검증

```bash
python -m pip install -e desktop
QT_QPA_PLATFORM=offscreen python -m unittest discover -s desktop/tests -v
node --test server/quote-requests/tests/*.test.cjs
QT_QPA_PLATFORM=offscreen python -m namufarm_desktop --self-check
```

실제 Apps Script 소스를 메모리 시트 fixture에서 실행하며 테스트 고객·키만 사용합니다. 운영 시트에 테스트 주문을 넣지 않습니다. GitHub CI는 Linux 테스트 후 Windows에서도 검사하고 실행 파일을 만들며 패키지 시작을 확인합니다.

설계 참고: [카페24 주문·배송 관리](https://www.cafe24.com/commerce/manage/order.html)의 상태별 업무·일괄 송장 입력, [로젠 공식 조회](https://www.ilogen.com/web/personal/tkSearch?t=1)의 11자리 송장 안내. 화면과 코드는 나무팜 업무에 맞게 별도로 작성했습니다.

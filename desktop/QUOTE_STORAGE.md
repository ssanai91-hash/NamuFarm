# PC 견적 자료 흐름

버전은 0.4.9를 유지합니다. 기존 Apps Script API를 사용하며 이번 변경에 서버 배포는 필요하지 않습니다.

- **견적요청**: `가져오기`와 10분 자동 가져오기는 매번 서버의 현재 신규 요청을 조회합니다. 이전 PC 요청 순번·삭제 기록과 비교하여 조회를 차단하지 않습니다. 완전한 페이지·스냅샷 검증은 유지하며, 조회 실패 시 이번 실행에서 마지막으로 성공한 목록을 유지합니다. 재시작 시 이전 로컬 요청은 표시하지 않습니다.
- **확정**: 서버 `save_quote_pricing`의 요청 ID·성공 여부·견적확정 상태를 확인한 뒤에만 `나무팜-확정견적.xlsx`를 갱신합니다. 저장 직후 다시 목록을 조회하지 않으므로, 후속 조회 실패가 확정 실패로 바뀌지 않습니다.
- **확정 견적**: PC 보관함(`namufarm-vault.db`)과 같은 폴더의 위 엑셀만 읽습니다. 시작할 때도 서버를 호출하지 않습니다. 서버에서만 확정한 견적을 재구성하거나 자동으로 가져오지 않습니다. 첫 실행에 기존 PC 초안과 로컬 확인 상태가 함께 있는 확정 견적만 한 번 이관합니다. 기존 초안 자체는 별도로 보존합니다.
- **복구**: 서버 응답이 유실되면 보호된 PC 보관함에 동일 요청·가격·견적 ID를 유지하고 `가져오기`로 재확인합니다. 서버 성공 확인 뒤 엑셀이 열려 있으면 이전 파일을 보존하며, 파일을 닫고 가져오기를 누르거나 재시작하면 확인된 견적을 저장합니다. 읽을 수 없거나 사라진 엑셀은 빈 파일로 덮어쓰지 않습니다.
- **후속 처리**: 배송정보 수정·발송완료 상태를 로컬 엑셀에 반영합니다. 입금확인 판매가 서버에 저장되면 엑셀에서 입금확인 상태로 보관하고 확정 견적 목록에서 제외합니다. 확정 견적의 삭제는 로컬 엑셀만 변경합니다. 판매관리·배송·매출 화면의 가져오기는 기존 판매 동기화·전송 대기·충돌 검증을 사용합니다. 견적요청 조회는 판매 전송 대기와 분리합니다.

엑셀의 `견적확정` 시트에는 품목별 고객·수량·단가·금액·상태를 표시합니다. 숨겨진 `앱보관자료` 시트에 주소·원가·발행자 등 전체 자료와 식별자를 보존하며 프로그램은 이를 읽습니다. 앱 관리 파일이므로 시트를 직접 편집하는 용도가 아닙니다. 전화번호와 고객 문자열은 수식이 아닌 텍스트로 저장하고, 새 파일을 완성한 후 기존 파일을 원자적으로 교체합니다.

현행 서버 API는 견적요청/견적확정 자료를 한 목록으로 반환할 수 있으므로 PC에서 신규 요청만 골라 표시합니다. 서버 확정 견적을 로컬 엑셀로 취합하는 별도 기능은 추후 구현 대상입니다.

## 격리 검증

`PYTHONPATH=desktop:desktop/tests python -m unittest test_confirmed_excel test_quote_storage_ui`

임시 보관함·엑셀과 실제 Apps Script 코드를 실행하는 메모리 서버 fixture만 사용합니다. 운영 계정·고객·문자·메일 발송은 사용하지 않습니다. Windows 설치 파일 컴파일, 실제 Excel 잠금·재저장 및 운영 서버 검증은 로컬에서 진행합니다.
